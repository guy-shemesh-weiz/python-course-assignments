# Course Statistics & Analysis Tools

This directory contains tools for analyzing course submission data from GitHub issues, including tracking student submissions, identifying late submissions, and generating comprehensive statistics.

## Overview

The workflow consists of two main components:

1. **issue_puller.sh** - Data extraction script
2. **course_statistics.py** - Data analysis script

---

## issue_puller.sh - GitHub Issue Extraction

### Purpose

The `issue_puller.sh` script fetches all GitHub issues from the course repository and exports them in a structured format for analysis.

### What It Does

- Uses the GitHub CLI (`gh`) to query all issues from the repository `Code-Maven/wis-python-course-2025-10`
- Retrieves **all issues** (up to 10,000) with all states (open and closed)
- Extracts the following fields for each issue:
  - **number** - GitHub issue ID
  - **state** - Issue status (OPEN or CLOSED)
  - **title** - Issue title (contains student name and assignment information)
  - **createdAt** - When the issue was created (ISO 8601 UTC timestamp)
  - **closedAt** - When the issue was closed (ISO 8601 UTC timestamp, or empty if still open)
- Exports data as **tab-separated values** (TSV) to `issues.txt`

### How to Run

```bash
bash issue_puller.sh
```

### Output

Creates `issues.txt` with tab-separated columns:

```
244	OPEN	Day09 by ..	2026-01-10T11:21:55Z
```

### Requirements

- GitHub CLI (`gh`) installed and authenticated
- Access to the course repository

## course_statistics.py - Analysis Script

### Purpose

Analyzes course submission statistics by processing GitHub issues and comparing submissions against assignment deadlines.

### What It Fetches & Analyzes

The script generates a comprehensive statistics report with six main sections:

#### 1. **Registered Students**

- Counts unique students from the course README's student roster
- Extracts student list from the `## Students` section in `course_readme.md`
- Total: 32 registered students

#### 2. **Open Issues**

- Shows the total number of currently open GitHub issues
- Provides a snapshot of ongoing discussions and work

#### 3. **Oldest Open Issues**

- Lists the 10 issues that have been open the longest
- Helps identify stale or long-standing issues needing attention

#### 4. **Missing Submissions**

- Analyzes submission status for each assignment:
  - Day 01-06 (regular assignments)
  - Day 08-09 (additional assignments)
  - Final Project proposal
  - Final Project submission
- Tracks which students haven't submitted each assignment
- Shows completion percentages per assignment

#### 5. **Late Submissions**

- Identifies all submissions made after assignment deadlines
- Lists for each late submission:
  - Student name
  - Days late
  - Actual submission timestamp
  - Deadline timestamp
- Groups late submissions by assignment

#### 6. **Unparseable Issues**

- Reports issues that couldn't be fully parsed or attributed to students
- Includes reason for why each issue couldn't be parsed
- Useful for debugging data quality issues

### How Assignment Tracking Works

The script determines submission status by:

1. **Extracting student names** from issue titles using fuzzy matching against the student roster
2. **Extracting assignment days** from issue titles (e.g., "Day 03", "Day04", etc.)
   - Handles variations: "day03", "Day 3", "DAY04" (case-insensitive)
   - Supports multi-day issues: "Day 05 and 06" (counts for both days)
3. **Recording submission timestamps** from issue creation dates (`createdAt` field)
4. **Comparing against deadlines** defined in the `DEADLINES` dictionary
5. **Marking as late** if submission date > deadline date

### Key Data Semantics

- **Issue opened_date** = When the student **submitted** the assignment (createdAt)
- **Issue closed_date** = When the issue was reviewed/closed (closedAt)
- **Deadlines** = Assignment due dates (used to calculate late submissions)
- **Time zone** = All timestamps are in UTC

### Data Sources

The script uses two input files:

#### issues.txt (Generated by issue_puller.sh)

- Tab-separated values file with columns:
  - `issue_id` - GitHub issue number
  - `status` - OPEN or CLOSED
  - `title` - Issue title containing student name and assignment info
  - `opened_date` - Issue creation timestamp (ISO 8601 UTC)
  - `closed_date` - Issue closure timestamp (ISO 8601 UTC, or empty)

#### course_readme.md

- Course README with assignment deadlines in the format:
  ```
  ## Deadlines
  - Day 01: 2025-11-01 22:00 UTC
  - Day 02: 2025-11-09 22:00 UTC
  ...
  ```
- Contains the `## Students` section with markdown table of registered students:
  ```
  | [Student Name](url) | ... |
  ```

### Output Files

#### 1. Console Report

Prints formatted statistics to stdout with:

- Student and issue counts
- Missing submission analysis
- Late submission tracking
- Issues that couldn't be parsed

#### 2. assignment_summary.csv

Summary table with completion metrics:

```
Assignment,Submitted,Missing,Total,Completion %
Day01,32,0,32,100.0%
Day02,30,2,32,93.8%
Day03,27,5,32,84.4%
...
```

#### 3. unparseable_issues.csv

Debug log for issues that couldn't be fully parsed:

```

```

## Data Generation: From subjects.txt to issues.txt

### Historical Context

Initially, the course tracking used a `subjects.txt` file that contained student submissions with **only the last update timestamp**. This made it impossible to accurately track:

- When assignments were first submitted
- Which students submitted late
- Complete submission history
- Differentiate between original submissions and subsequent edits

### Solution: Generating issues.txt

To overcome the limitations of `subjects.txt`, we implemented the `issue_puller.sh` script to:

1. **Extract direct GitHub data** - Pull the actual creation timestamps from GitHub issues instead of relying on recorded updates
2. **Capture full history** - Get both creation dates (submissions) and closure dates (reviews)
3. **Enable late submission tracking** - With accurate submission timestamps, we can now compare against deadlines and identify late submissions
4. **Provide rich metadata** - Include issue status, full titles, and complete timestamps for comprehensive analysis

### Key Improvements Over subjects.txt

| Aspect                    | subjects.txt             | issues.txt                                   |
| ------------------------- | ------------------------ | -------------------------------------------- |
| Submission date           | ❌ Only last update date | ✅ Issue creation date (accurate submission) |
| Review/closure date       | ❌ Not available         | ✅ Issue closure date included               |
| Complete history          | ❌ Only latest state     | ✅ Full issue history available              |
| Late submission detection | ❌ Impossible            | ✅ Enabled with accurate dates               |
| Data source               | Manual entry             | Direct from GitHub                           |
| Data accuracy             | Subject to errors        | Single source of truth                       |

## Debugging & Troubleshooting

### Checking Unparseable Issues

If the script reports unparseable issues, check `unparseable_issues.csv`:

```bash
cat unparseable_issues.csv
```

Common reasons:

- **"Could not identify student"** - Issue title doesn't contain a recognizable student name
- **"Could not identify assignment days"** - Issue doesn't mention which assignment day it relates to

### Manual Issue Review

To examine a specific issue in detail:

1. Find the issue number in `unparseable_issues.csv`
2. Review the GitHub issue online
3. Determine if it's:
   - A genuine submission that needs better parsing logic
   - A meta-issue or administrative item (should be ignored)
   - A formatting problem in the issue title

### Re-running the Analysis

After fixing data issues:

```bash
python course_statistics.py
```

This will regenerate all reports with updated data.

## Script Architecture

### extract_students_from_readme()

Parses the `## Students` section of `course_readme.md` to extract the authoritative student roster.

### find_student_in_title()

Uses fuzzy matching to identify which registered student is mentioned in an issue title.

### extract_days_from_title()

Parses issue titles to extract assignment day numbers, handling various formats and multi-day submissions.

### analyze_assignment_submissions()

Core analysis function that processes all issues, matches students and assignments, calculates late submissions, and tracks unparseable issues.

### print_statistics()

Formats and displays all statistics sections in a human-readable format.

## Notes

- Day 07 is excluded from tracking (marked as TBD)
- All timestamps are in UTC
- Late submissions are calculated as `(submission_date - deadline) days`
- Fuzzy matching requires a minimum confidence score of 50 points
- The script is idempotent - running it multiple times produces the same results
